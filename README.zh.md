# dsh-session-workspace

[English](./README.md) | 中文

把现有 DeepSeek Harness session 移动到另一个已注册工作区，同时保持 session ID 和对话历史不变。

插件提供两个入口：会话 **⋯ → 移动到其他工作区 → 选择目标**，以及把会话行拖入目标工作区的整个侧边栏分组。目标区域包含文件夹／标题行、会话行与组内留白。两个入口共用经过 DSH 认证的迁移接口，保留原会话 ID 和完整事件历史，更新持久化的 `cwd` 与工作区归属。旧代际文件保留在会话索引目录外的备份中。

## 安全设计

- DSH `0.2.0-rc.2` 支持已打开的空闲 session：先锁住该 Agent 的新输入，等待原生完整生命周期释放写入者，再迁移并以原 ID 恢复。运行中、维护中或有待处理输入时拒绝移动，不取消工作。
- 已加载会话的释放使用此版本的内部适配。严格校验宿主版本，以及单会话生命周期标签与 Agent scope 的元数据身份；接口未知或匹配不唯一时拒绝释放。其他版本仍仅支持冷 session。
- 目标必须是 DSH 中已经注册的现有工作区。
- 绝不覆盖目标位置已有的 session 文件。
- 提交前会再次核对源文件修订；准备期间发生变化会直接拒绝。
- 移动期间持有源位置和目标位置的原生写入锁，排除其他 DSH 写入者。
- 所有原始代际文件都会持久备份到 `<DSH_HOME>/session-workspace-backups/<uuid>/`。
- 如果更新工作区账本失败，文件和原工作区归属都会自动回滚。

## 要求

- V4 后端和两个侧边栏入口支持 DeepSeek Harness `0.2.0-rc.2`，通过第一方 `@deepseek-ai/dsh-session-format-catalog` 校验准备好的完整日志；原有 V3 原生迁移分支与 `0.1.5` 的有限菜单兼容路径保留。
- 已发布的 `v0.2.0` tag 针对 DSH `0.1.5-rc.1`；在 DSH `0.2.0-rc.2` 上请使用包含 V4 修改的源码版本。DSH `0.1.1-rc.2` 请继续使用插件 `0.1.1`。
- 默认的逐 session JSONL 持久化后端（`.jsonl.zstd` 或 `.jsonl`）。共享 SQLite 后端没有独立 session 文件，插件会明确拒绝，避免不安全改库。
- 支持 DSH 所用 Zstandard API 的 Node.js；DSH 官方支持的 Node 运行时已经具备。

## 安装

```sh
npm ci
npm run build
npm pack
dsh plugin --profile web add ./dsh-session-workspace-0.2.7.tgz
```

官方桌面应用请改用 `--profile desktop`。

安装后重启 DSH Web 进程。包内的 `cordis.patch.yml` 会同时挂载 trusted-host RPC 和浏览器客户端。

## 更新

在插件详情页先关闭整个 `dsh-session-workspace` 插件包，等待组件停止，再安装新归档并重新开启。DSH `0.2.0-rc.2` 会缓存同一 URL 的 Host 模块；每版归档使用包含全部迁移代码的独立 Host 入口，因此完成插件包卸载／重新挂载后可加载新版，无需重启其他服务。单独更新包文件或刷新插件列表不能证明 Host 已更新。行间插入还会检查服务端能力；旧 Host 不支持时在迁移前提示重新加载。

原生迁移分支支持 V3 与 V4 的 JSONL generation 和 write-lease hook。V4 使用第一方格式 catalog，因为新版持久化后端已不再提供 `createRestore`。压缩文件逐帧完整解码，准备好的完整文件在发布前重新验证；身份认证和 trusted-host 检查仍由 DSH 执行。未来存储版本需要重新检查兼容性。

## 使用

1. 等待待迁移会话空闲，且没有排队输入。DSH `0.2.0-rc.2` 的已打开会话无需重启应用；当前显示的会话会暂时释放视图，完成后按原 ID 重新打开，可继续对话。若移动过程中你选择了其他会话，插件不会抢回视图。无法验证或释放界面引用时，迁移前会明确拒绝。
2. 任选一个入口：
   - **菜单：** 打开该会话的 **⋯**，点击 **移动到其他工作区**，选择目标工作区并确认。
   - **拖动：** 在按工作区分组的侧边栏中，把会话行拖到目标分组的文件夹／标题行、会话行或组内留白。目标会话行的上／下半部对应插入到该会话前／后，目标侧蓝线标明准确位置；等待高亮与蓝线后松手。标题或组内留白采用默认位置；结果或拒绝原因会以提示显示。

有效目标工作区高亮时，插件隐藏残留的原生会话排序线，并在侧栏树外绘制目标插入线，使源区域的隐藏规则不会误藏目标蓝线；离开目标或结束拖动后恢复原生提示。同工作区内的会话排序、工作区分组拖动仍由 DSH 处理。平铺列表没有工作区拖放目标，请使用菜单。

定位拖放通过公开的工作区排序 API 保存相对锚点，并调用 DSH 现有共享侧栏 Store action 保存完整显示顺序，自动切到原生手动排序；隐藏／归档成员及其他账户顺序保留。空白／新会话与置顶分区仍按 DSH 的固定布局显示，无法实现的分区边界会在迁移前拒绝。会话 ID、历史、置顶及归档状态均保留。

迁移后 session ID 不变，会出现在目标工作区下；后续 shell、文件系统和 sandbox 操作都会使用目标工作区路径。

宿主没有公开的单会话关闭接口。已加载会话适配仅调用原生 `agentLoop.lifecycle(id)` 的完整释放回调，不单独删除 registry 或卸载 scope fiber；它等待 writer 关闭后验证原生写锁可重新取得。客户端的 `clearMain()` 同样是此版本的内部兼容接口。客户端订阅原生引用状态，最多等待两秒，让当前会话的所有界面引用释放后创建新的历史 generation；引用仍保留或用户选中了其他会话时停止移动，不强制关闭其他视图。重新打开原 ID 使用公开 `openSession()`。这两处都不应被视为未来 DSH 版本的稳定 API。

## 卸载

```sh
dsh plugin --profile web remove dsh-session-workspace
```

## 开发验证

```sh
npm test
npm pack --dry-run
```

将 `DSH_NATIVE_ROOT` 指向包含 `node_modules` 的已安装 DSH 包根目录，可运行原生持久化与真实持久工作区账本测试：

```sh
DSH_NATIVE_ROOT=/path/to/installed/dsh node --expose-internals --test tests/*.test.mjs
```

测试自行创建临时会话／存储根目录。真实账本测试会重建整个服务栈，检查重启后的 ID、完整历史、归属、置顶／归档状态和后续写入。DOM 测试覆盖两个入口、原生排序透传、重复拖放抑制、可见拒绝与卸载清理。

测试使用真实临时文件和 Node Zstandard codec，覆盖成功迁移、备份、活动 session 拒绝、目标冲突、修订竞态、失败回滚、RPC 返回和侧边栏 session 定位。
